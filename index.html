How JSON Dies at Scale

JSON repeats "qualified_name":, "kind":, "score":, "provenance":, "distance": on every single record. At 500 symbols, that's 2,500 structurally identical tokens carrying zero semantic content.

  • GPT-5.5 returns empty strings. Not wrong answers. Nothing. The model receives 53,341 tokens of repeated field names and cannot produce any response.
  • Claude Opus miscounts 500 as 356. Then enumerates manually. 143 lines of chain-of-thought. Still wrong.
  • Every model fails distance filtering. Correct answer: 166. Opus answers 200. GPT-5.4 answers 300-404. GPT-5.4-mini answers 300.

JSON median error magnitude: 56. GCF median error magnitude: 4.

Why GCF Works Where JSON Fails

GCF answers are structural, not computational. Instead of 500 JSON objects to parse and filter, GCF uses section headers that encode groupings directly:

## targets [166]
@0 fn pkg.HandleRequest 0.95 lsp_resolved
@1 type pkg.ProcessResponse 0.74 ast_inferred
## related [167]
@2 method pkg.ValidateConfig 0.52 structural

"How many targets?" Read the header: [166]. Done. No column scanning. No attention decay across 500 flat rows. The answer is structural, not computed.

Session Statefulness

GCF is the only format with cross-call deduplication. Symbols seen in prior tool calls are referenced by ID instead of re-serialized. JSON re-serializes everything on every call.

By the 5th tool call in a session: 92.7% token savings over JSON. The per-call advantage compounds across every interaction.

GCF was designed for the machine reading it. JSON was designed for humans. The consumer of your API responses is not a human.
